# Delegated Claude Code context and runtime boundaries

Qualified pair: Agent SDK 0.3.274 and installed Claude Code CLI 2.1.280. Installed-CLI synthetic tests cover prompt-submit context, canonical MCP skill text, parallel native tool-ID correlation and mandatory policy denial under native bypass mode. Isolated live provider checks passed for workspace instructions, persisted todos and result metadata, skill loading after process resume, and a fresh native-profile session. Billing category was not measured.

The interactive SDK process uses `claude_code` preset plus a short, separate behavior append in the default `redsun` profile. One-shot title/summary requests retain their tool-free path and no append. Ordinary API-backed Claude models do not use this adapter.

`SessionRunner.prepareContext` commits canonical `InstructionState` updates. `SessionContext.select` assembles built-ins, discovered files, skills, references, MCP rules and session instruction entries; `context.load` renders the persisted epoch baseline. The delegated adapter does **not** replay that full host prompt or pretend the native transcript is redsun history. Instead, it reads the already-discovered file list (including project memory) and sends sourced updates through the SDK's `UserPromptSubmit` `additionalContext`, never by prefixing a user message with a forged host marker. Claude's user/project/local setting sources remain active, so `CLAUDE.md` is left to the native loader. The memory policy accompanies its discovered memory file. Arbitrary `event.system` additions from per-model plugin hooks are not promoted to native instructions: they may depend on host-only tools or change at a different cadence.

The agent ID, mode, system text and worker status form a per-session revision. Host context is acknowledged once the SDK calls the submission hook for the captured turn; a failed turn _before submission_ retries, while an already submitted prompt is not duplicated because a later model result fails. A new native process, including persisted-cursor resume, eviction or permission-mode replacement, re-establishes current context. The preset append is a startup option; model and permission mode have live SDK setters. The callback reads the current turn binding rather than capturing an obsolete turn at process creation. Asynchronous compact restoration checks cancellation and native-process/turn-binding identity before mutating tracking state or acknowledging delivery, so stale callbacks cannot overwrite a newer turn. It does not parse or trust arbitrary user-authored `<system-update>` text.

The skill catalog comes from Location-scoped `Skill.Service`, filtered by the agent's skill rules and effective session `Permission.inspect` decisions, excluding non-autoinvokable or undescribed entries. It is exposed only when the captured host `skill` tool is available. IDs, names and descriptions are revision-tracked as one small catalog, delivered again on change, resume or compaction; skill contents still load through the real host tool. Native CLI skills may coexist through inherited settings, so the catalog explicitly names redsun IDs and its loader rather than pretending all native skills belong to redsun.

The discovery source is Location-scoped: the config instruction plugin walks only applicable ancestor `AGENTS.md` files from the location to its project/home boundary. Do not widen this to every file in a repository. The actual Step assistant ID is carried in a delegated-only request header, rather than guessed from the most recent persisted message. One `Tool.Snapshot` is captured per turn using the selected agent and session permissions, then its exposed MCP definitions are intersected with tools advertised on that model request. In the redsun behavior, this includes `execute` and exact registered names from the host's connected direct-MCP tool inventory (`codemode: false`), never an arbitrary host-tool name or a second Claude-side connection to MCP servers. Code Mode's canonical snapshot catalog is revision-tracked in the SDK submission and compaction hooks; nested calls run through the same host snapshot and leaf permissions. Resources, prompts and MCP server instructions are **not** mirrored. Native behavior retains its subagent-only host bridge.

The MCP server holds a stable getter and binds the current snapshot before initial CLI tool discovery. A changed exposed name or input schema replaces the idle native process; Code Mode inventory and description changes use the hook instead of restarting it. `PreToolUse` uses `Permission.inspect` (nonprompting), while `canUseTool` owns interactive approvals; the same session-scoped policy instance serves both. `PostToolUse` commits native plan exits. Translated provider-executed tool events remain the sole visible lifecycle rows. The redsun profile disallows verified overlapping native todo/task tools; native profile retains their availability. Host result metadata is retained only when the MCP execution has a verified native tool-use ID, never by equating MCP request IDs with native IDs.

| Boundary                                      | Expected behavior                                                        |
| --------------------------------------------- | ------------------------------------------------------------------------ |
| First interactive turn                        | Preset append; agent/files/skills via UserPromptSubmit additionalContext |
| Unchanged turn                                | Fresh user content only                                                  |
| Same-agent edit, memory/skill edit or removal | Updated sourced context once at SDK submission                           |
| Failure/cancellation before submission        | Retry unacknowledged context                                             |
| Process replacement/resume                    | Re-establish current instructions; no host transcript replay             |
| One-shot/API-backed model                     | No delegated append or context bridge                                    |
| Native profile                                | Native preset and inherited settings; delegated agent/mode brief remains |

Native `SessionStart` with `source: "compact"` supports `additionalContext` after manual and automatic compaction. It rebuilds the same provenance-filtered agent/files/skill snapshot through the current turn binding and acknowledges the new epoch at hook delivery. `compact_boundary` signals are counted separately: settlement clears the snapshot only when fewer compact hooks succeeded than boundaries observed, leaving the next eligible message as the fallback for an absent or failed hook. Multiple compactions within a turn and cancellation before hook delivery follow that same rule. The installed Agent SDK 0.3.274 and explicitly selected CLI 2.1.280 were exercised against a credential-free loopback upstream: manual `/compact` restored context on the following prompt's first request; automatic compaction restored context on the first post-summary request **within the same native turn**. PATH currently selects CLI 2.1.281 for the other synthetic tests. Loaded skills, references, MCP instructions and other plugin context need separately reviewed provenance and deduplication, not blanket copying. A clean profile rollback requires a fresh native session because prior context cannot be removed from a resumed transcript.
